# Motion Automation Hub

استودیوی محلی موشن‌گرافیک با HTML، CSS، JavaScript و GSAP. نسخهٔ ۱.۳.۱ شامل دریافت کد موشن، پیش‌نمایش و خروجی MP4 با سرور محلی است. کد می‌تواند بیرون از سرور توسط مدل رسمی AI تولید شود؛ اتصال به مدل و اتوماسیون محلی فعلاً پیاده‌سازی نشده‌اند.

## خروجی ریلز از کد

با Chrome/Edge نصب‌شده (یا Chromium) و FFmpeg طبق [راهنمای رندر](docs/rendering.md)، `npm run render:code` یک MP4 عمودی از `motion/reel.js` می‌سازد. `npm run render:reel` مسیر سناریو به ویدئو را اجرا می‌کند. سرور `npm start` نیز از `POST /api/renders` کد آماده می‌گیرد و وضعیت و MP4 را برمی‌گرداند. پیش‌نمایش کد با کنترل پخش در مسیر `/code-preview/` است.

## مسیر اصلی: تولید خودکار

سناریوی سادهٔ `scenarios/demo.json` را بنویسید؛ مولد، موقعیت عناصر و ورود/مکث/خروج هر صحنه را می‌سازد. توسعهٔ پنل دستی اولویت پروژه نیست. جزئیات قرارداد، محدودیت‌ها و نمونهٔ ورودی در [راهنمای خودکارسازی](docs/automation.md) است.

پس از نصب وابستگی‌ها، `npm run auto` خروجی `projects/generated.json` را تولید و پیش‌نمایش آن را اجرا می‌کند. `npm start` برای پروژهٔ دستی قبلی باقی مانده است. کنترل‌های پخش، مکث، شروع مجدد و seek در هر دو حالت فعال‌اند.

## راه‌اندازی در Windows PowerShell

نیازمندی: Node.js نسخهٔ 22 یا بالاتر همراه npm.

```powershell
Set-Location C:\Motion_Automation_Hub
npm ci
npm start
```

سرور محلی روی پورت 5500 اجرا می‌شود و مسیر `/` یا `/apps/studio/` استودیو را نمایش می‌دهد. برای توقف `Ctrl+C` بزنید. در محیط ابری پوشهٔ پروژه `/workspace/motion-automation-hub` است.

## ویرایش پروژه

در پنل «ویرایش پروژه» عنصر را انتخاب کنید و متن، رنگ یا موقعیت X و Y آن را تغییر دهید. می‌توانید رنگ پس‌زمینه، زمان شروع، مدت، الگوی حرکت و منحنی سرعت را هم تغییر دهید. گزینه‌های «ورود از پایین»، «ورود از چپ»، «ورود با محوشدن» و «خروج با محوشدن» حرکت انتخاب‌شده را جایگزین می‌کنند؛ حرکت جدیدی به پروژه اضافه نمی‌شود. «منحنی سرعت» فقط تغییر سرعت در طول همان حرکت را تنظیم می‌کند. برای عنصری با چند حرکت، حرکت موردنظر را از فهرست انتخاب کنید.

۱. «اعمال و پخش پیش‌نمایش» تغییرات معتبر را بدون نوشتن فایل اعمال می‌کند و از زمان شروع حرکت انتخاب‌شده پخش می‌کند. بنابراین متن در فریم صفر نامرئی نمی‌ماند. با دکمهٔ مکث یا اسلایدر می‌توانید فریم را بررسی کنید.
۲. «ذخیره در فایل پروژه» ویرایش‌های فرم را هم اعمال می‌کند، دوباره اعتبارسنجی می‌کند و `projects/demo.json` را ذخیره می‌کند.
۳. «بارگذاری مجدد JSON» آخرین نسخهٔ روی دیسک را می‌خواند؛ پیش از کنارگذاشتن تغییرات ذخیره‌نشده تأیید می‌گیرد.

پیام زرد وضعیت ذخیره و پیام زیر پیش‌نمایش نتیجه یا خطا را نشان می‌دهند. در صورت ورودی نامعتبر، فایل و آخرین پیش‌نمایش معتبر حفظ می‌شوند. پخش پس از بارگذاری خودکار آغاز نمی‌شود.

نسخهٔ قبلی فایل پیش از هر ذخیره در `server/storage/backups/` نگه داشته می‌شود. پشتیبان‌ها محلی و خارج از Git هستند. نوشتن فایل با فایل موقت و جایگزینی انجام می‌شود؛ اگر ساخت پشتیبان شکست بخورد، فایل پروژه جایگزین نمی‌شود. پشتیبان‌ها خودکار حذف نمی‌شوند.

برای بازگرداندن پشتیبان، سرور را متوقف کنید، از فایل فعلی یک کپی بگیرید، فایل پشتیبان دلخواه را روی `projects/demo.json` کپی کنید و سرور را دوباره اجرا کنید. مسیر کامل در نصب پیشنهادی Windows: `C:\Motion_Automation_Hub_Ready\server\storage\backups`.

اگر پروژه در تب دیگری یا بیرون از برنامه تغییر کرده باشد، ذخیره با خطای تعارض رد می‌شود؛ متن و مقادیر ویرایش خود را یادداشت کنید، بارگذاری مجدد بزنید و دوباره اعمال کنید. قفل ذخیره مربوط به یک فرایند سرور است؛ هم‌زمان دو سرور روی همان پوشه اجرا نکنید.

ویرایش مستقیم `C:\Motion_Automation_Hub\projects\demo.json` نیز همچنان پشتیبانی می‌شود. پس از آن «بارگذاری مجدد JSON» را بزنید.

- `elements`: متن و دایره، موقعیت، ابعاد، رنگ و اندازهٔ قلم.
- `animations`: شناسهٔ عنصر مقصد، زمان شروع و مدت بر حسب ثانیه، easing، مقادیر `from` و `to`.
- ویژگی‌های متحرک مجاز: `x`، `y`، `opacity`، `scale` و `rotation`.
- موقعیت پایهٔ عناصر از گوشهٔ بالا و چپ بر حسب پیکسل طراحی محاسبه می‌شود. `x` و `y` انیمیشن نسبت به موقعیت پایه‌اند. پیش‌نمایش متناسب با فضای نمایش کوچک می‌شود.
- ابعاد، FPS و مدت در JSON ذخیره می‌شوند؛ FPS فعلاً فقط فراداده است و نرخ نمایش مرورگر را تعیین نمی‌کند.

سرور JSON را با `packages/motion-engine/project.schema.json` اعتبارسنجی می‌کند. شناسه‌های تکراری، مقصد ناموجود، زمان‌بندی خارج از مدت پروژه و ویژگی‌های ناشناخته رد می‌شوند. هیچ رشته‌ای از JSON به‌صورت کد JavaScript اجرا نمی‌شود؛ متن با `textContent` درج می‌شود.

هم‌پوشانی حرکت‌های یک ویژگی روی یک عنصر با خطای اعتبارسنجی رد می‌شود. چند صحنه از طریق مولد سناریو پشتیبانی می‌شود؛ پنل دستی برای پروژه‌های ساده و بازبینی باقی مانده و تایم‌لاین با کشیدن و رهاکردن ندارد.

## تست

```powershell
Set-Location C:\Motion_Automation_Hub
npm test
# فقط بار اول برای آزمون مرورگر، با اینترنت:
npx playwright install chromium
# تست مرورگر، سرور و فایل پروژهٔ موقت خودش را می‌سازد:
npm run test:browser
```

می‌توانید مسیر Chromium نصب‌شده را به‌جای دانلود تعیین کنید:

```powershell
$env:CHROMIUM_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
npm run test:browser
```

آزمون مرورگر پخش و seek تکرارپذیر، ویرایش متن/رنگ/موقعیت/زمان‌بندی، ذخیره و پشتیبان، ماندگاری پس از بارگذاری، رد ورودی نامعتبر، تعارض دو نسخه، لغو کنارگذاشتن ویرایش‌ها، بازیابی خطای بارگذاری و چیدمان موبایل را بررسی می‌کند. تست، تغییر فریم واقعی هنگام ورود و خروج، ذخیره و بازیابی نوع حرکت، اعمال تغییر از فریم صفر و تشخیص سرور قدیمی را هم بررسی می‌کند. فایل نمونهٔ مخزن در این تست تغییر نمی‌کند. تست‌های Node.js نیز API، اعتبارسنجی، ذخیرهٔ هم‌زمان و خرابی پشتیبان‌گیری را بررسی می‌کنند. تصویر آزمایش در `test-results/studio.png` ذخیره می‌شود.

## تفکیک اجزا

- `apps/studio/`: رابط و کنترل‌های پیش‌نمایش.
- `packages/renderer/`: ثبت فریم دقیق با Playwright و ساخت MP4 با FFmpeg.
- `motion/reel.js`: نمونهٔ کد موشن عمودی با قرارداد composition/createMotion.
- `server/render-jobs.js`: وضعیت کارهای رندر HTTP.
- `packages/scenario-engine/`: کامپایل سناریوی ساده به پروژهٔ چندصحنه‌ای.
- `scripts/generate.js`: تولید تکرارپذیر پروژه از خط فرمان.
- `scenarios/demo.json`: نمونهٔ ورودی خودکار سه‌صحنه‌ای.
- `packages/motion-engine/`: Scene Builder، قرارداد JSON و اعتبارسنجی.
- `server/index.js`: سرور Node.js، API اعتبارسنجی/ذخیره و ارائهٔ فایل‌های محلی مجاز.
- `server/project-store.js`: ذخیره، کنترل نسخهٔ فایل و پشتیبان‌گیری.
- `projects/demo.json`: پروژهٔ نمونهٔ ۱۰ ثانیه‌ای 1920×1080.
- `tests/`: تست‌های Node.js و آزمون واقعی مرورگر.

پس از نصب وابستگی‌ها، اجرای استودیو به اینترنت، CDN یا API ابری وابسته نیست. فونت فعلاً از فونت‌های سیستم استفاده می‌کند؛ برای خروجی یکسان روی دستگاه‌های مختلف، در مرحلهٔ رندر به فونت محلی ثابت نیاز داریم. پروژهٔ media-mcp تغییری نمی‌کند.

## به‌روزرسانی نسخهٔ نصب‌شده از GitHub

ابتدا سرور را با Ctrl+C متوقف کنید. در پوشهٔ نسخهٔ نصب‌شده اجرا کنید:

```powershell
Set-Location C:\Motion_Automation_Hub_Ready
git pull --ff-only origin motion-studio-base
if ($LASTEXITCODE -ne 0) { throw "Git update failed; keep local changes and inspect the error." }
npm ci
if ($LASTEXITCODE -ne 0) { throw "Dependency installation failed." }
npm test
if ($LASTEXITCODE -ne 0) { throw "Tests failed; do not start the new version." }
npm start
```

از reset یا حذف تغییرات محلی برای رفع خطای Git استفاده نکنید. این نسخه فایل نمونهٔ `projects/demo.json` را تغییر نمی‌دهد. اگر قبلاً پورت دیگری تعیین کرده‌اید، `$env:PORT` در همان PowerShell برقرار می‌ماند. پس از شروع، از همان پورت استفاده کنید و Ctrl+F5 بزنید.

### اگر کنترل‌های ویرایش کار نکردند

بالای ویرایشگر باید «سرور ویرایشگر 1.3.1 متصل است» نمایش داده شود. اگر پیام ناسازگاری سرور دیدید، پس از git pull سرور قدیمی را با Ctrl+C متوقف و npm start را دوباره اجرا کنید؛ تازه‌کردن مرورگر به‌تنهایی فرایند Node.js را به‌روز نمی‌کند. سپس روی پورت همان سرور Ctrl+F5 بزنید. برای بررسی سرور:

```powershell
Invoke-RestMethod http://127.0.0.1:5500/api/status
```

اگر PORT دیگری تنظیم کرده‌اید، شمارهٔ پورت را عوض کنید. این درخواست باید version برابر 1.3.1 و protocol برابر project-editor/2 بدهد.
